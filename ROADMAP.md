# pdf-formatter — дорожная карта

Личный веб-редактор PDF. Основной сценарий — правка существующих PDF.
Спецификация: ISO 32000-1 (≈ Adobe PDF Reference 1.7), номера разделов ниже — по ней.

## Запуск

```bash
docker compose up --build        # http://127.0.0.1:8080
docker build --target test .     # все тесты, выходные файлы проверяет qpdf
./scripts/release.sh             # dist/: PDF-Formatter.dmg (macOS), zip для Windows и Linux
```

Сборка из `dist/` ни от чего не зависит: интерфейс и шрифты встроены в исполняемый файл (тег сборки
`embed`), рядом README.txt с инструкцией. macOS — приложение без значка в Dock, Windows — без окна
консоли; выключаются кнопкой в интерфейсе, повторный запуск открывает работающую копию. Порт —
`127.0.0.1:47321` (не 8080, чтобы не попадать в Docker/разработку), присоединяется только к другой
автономной копии. Данные — в папке приложения пользователя, примеров в сборке нет.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Язык ядра | Go, библиотека — пакет `pdf/` в этом же модуле, не импортирует ничего из `cmd/` |
| Фронтенд | Vite + Preact + TS; холст и оверлей блоков — чистый DOM |
| Отрисовка страниц | pdf.js в браузере (свой просмотрщик, не `PDFViewer`) |
| Запуск | Docker, один контейнер, слушает только `127.0.0.1`, без авторизации |
| Хранение | `/data` (volume): исходник + журнал правок, документы живут между сеансами |
| Сохранение | incremental update по умолчанию, «чистое сохранение» — полная перезапись |
| Правка контента | гибрид по сегментам: нетронутое пишется как было, изменённое — перегенерируется самодостаточным |
| Текст блоков | символ в символ: двойные и отдельно нарисованные пробелы, NBSP (WinAnsi `\240`), хвостовые пробелы сохраняются; `Flow` склеивает визуальные строки для правки (без вставок там, где уже есть пробел или перенос по дефису; короткая строка → `\n`); перенос строк (`Wrap`) не теряет символов |
| Векторные блоки | прямоугольные части (линии, рамки) объединяются при касании — сетка таблицы одним блоком; диагонали, кривые, точки — только с группой, нарисованной перед ними (узлы и рёбра графа по отдельности); касание штрихов — по геометрии отрезков. Наложенные друг на друга подписи — разные блоки |
| Устойчивость правок | правка исходного блока хранит его элементы (`Op.Members`, `layout.ItemID`): улучшение разбора на блоки не переносит старые правки на другое содержимое |
| Версии файла | `/file?v=rev` отдаёт ровно эту ревизию (последние 4 в памяти, иначе 410) с ETag — pdf.js читает кусками, и правки посреди чтения не подменяют байты |
| pdf.js | декодеры JPEG 2000/JBIG2/ICC (wasm), CMap и стандартные шрифты лежат рядом с приложением (`/pdfjs/`). Точки — вырожденные подпути с круглыми концами (так Quartz рисует узлы графов) — Chrome 154+ по спецификации canvas отбрасывает: `web/src/pdf.ts` достраивает им отрезок 0,001 |
| Шрифты в репозитории | `fonts/free` (OFL, Apache, ParaType FFL — в git и сборках) и `fonts/licensed` (коммерческие — в `.gitignore`, в сборку только с тегом `licensed`: `LICENSED=1 ./scripts/release.sh`); в библиотеке источник `licensed`, id встроенного шрифта не зависит от подпапки |
| Свои объекты | целиком генерируются из модели; модель — в `/PieceInfo` страницы |
| Единицы в UI | миллиметры (шрифты — pt), в модели всё в pt |
| Шрифт по умолчанию | PT Sans (OFL), шрифты Mac монтируются только на чтение |
| Новые страницы | A4 |
| SVG | свой конвертер на Go (базовое подмножество, о пропущенном — предупреждение) |
| Не делаем | OCR, AcroForm, расшифровку, CMYK/PDF-X/PDF-A |

## Архитектура

```
Браузер (Preact + pdf.js)                    Docker: cmd/server (net/http)
  просмотрщик, слой блоков, панели  ◄──────►   API, SSE, хранение в /data
                                     JSON+PDF   └ pdf/  ← библиотека
```

Ключевые идеи:
- **Исходник неизменен** → всё, что из него вычислено (объекты, анализ страниц), кэшируется бессрочно.
  Меняется только слой генерации — и только по страницам.
- **Каждый блок ссылается на диапазон операторов** content stream. Правка = операция над операторами.
- **Журнал операций**: исходник + журнал → новый PDF (чистая функция). Отмена = убрать последнюю операцию.
- **Картинка на экране строится из тех же байтов**, что уйдут в файл.

## Фазы

### Фаза 0. Каркас
- [x] Структура репозитория: `pdf/`, `cmd/server/`, `web/`
- [x] Dockerfile (`web` → `build` → `test` → `prod` distroless), `compose.yml`, `compose.dev.yml`
- [x] Порт только на `127.0.0.1`
- [x] Тестовый набор `testdata/corpus/`: Chrome, Quartz, cairo, 500 страниц (`testdata/make-corpus.sh`). Реальные PDF (Word, LaTeX, выписки) — докладывать сюда

### Фаза 1. Библиотека: объекты, чтение и запись (§7.2–7.5)
- [x] Лексер и парсер всех типов объектов, только `[]byte`
- [x] xref: таблица, потоки, object streams, `/Prev`, `/XRefStm`, восстановление сканированием
- [x] Фильтры: Flate (+ терпимость к битым потокам), PNG/TIFF-предикторы, LZW, ASCIIHex, ASCII85, RunLength
- [x] Ленивое разрешение ссылок, дерево страниц с наследованием
- [x] Writer: incremental update и чистое сохранение (с удалением неиспользуемых объектов)
- [x] Импорт: битый файл → чистая копия; зашифрованный → понятная ошибка
- [x] Копирование графа объектов между документами
- [x] Fuzz-тест парсера, round-trip на корпусе

### Фаза 2. Просмотрщик и список документов
